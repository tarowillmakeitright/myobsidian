# Mission: Make a Container Prove It Is Healthy

[[Home]]

#learning #mission #ai #devops #science

## Objective

Build a tiny Dockerized HTTP service with a real health check, then deliberately break it and observe how Docker reports the failure.

## Exact steps

1. **0–10 min — Create the service:** Make a small Python HTTP endpoint at `/health` that returns HTTP 200 and `{"status":"ok"}`.
2. **10–20 min — Containerize it:** Write a `Dockerfile`, build the image, and run it locally on port 8080.
3. **20–30 min — Add health checking:** Add a Docker `HEALTHCHECK` that calls `/health` every 5 seconds with a short timeout and three retries.
4. **30–40 min — Run a failure drill:** Change `/health` to return HTTP 500, rebuild/restart, and watch `docker inspect` transition the container from `healthy` to `unhealthy`.
5. **40–45 min — Capture the lesson:** Record the commands used, one healthy inspection result, one unhealthy result, and two sentences explaining why process-up is different from service-ready.

## Expected output artifact

A folder named `container-health-lab/` containing:

- the service source file
- `Dockerfile`
- `README.md` with run commands, healthy/unhealthy evidence, and the two-sentence takeaway

## Stretch challenge

Add a Docker Compose dependency that waits for this service to become healthy before starting, then verify the dependent container stays blocked during the failure drill.
