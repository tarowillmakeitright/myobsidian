# Mission: Build a Tiny RAG Evaluator (AI)

Tags: #learning #mission #ai #devops #science
Links: [[Home]]

## Objective
Create a minimal retrieval-augmented QA evaluator that measures whether better chunking improves answer quality on a small local document set.

## Exact Steps (30–60 min)
1. Create a folder `~/tmp/rag-mission` and add 3–5 text files (notes/docs you already have).
2. Write a short Python script (or notebook) that:
   - Splits docs into chunks (start with fixed-size chunks, e.g., 400 chars).
   - Embeds chunks (use any local/API embedding you already have access to).
   - Retrieves top-3 chunks for each query.
3. Define 5 test questions with expected key facts.
4. Run baseline evaluation:
   - For each question, generate answer from retrieved chunks.
   - Score manually 0/1 for “contains expected fact”.
   - Record total score.
5. Change chunking strategy (e.g., 200 chars + overlap 50) and rerun.
6. Compare baseline vs new strategy and write 3 bullet conclusions.

## Expected Output Artifact
A single note or markdown report containing:
- The 5 questions
- Baseline score vs revised score
- One table of results
- 3 practical takeaways for future RAG setups

## Stretch Challenge
Add a reranker step (or simple keyword rerank) and test whether it improves the revised score without changing embeddings.
