# Kubernetes Event Triage in 45 Minutes

Tags: #learning #mission #ai #devops #science
Links: [[Home]]

## Objective
Learn to quickly diagnose why a Kubernetes workload is unhealthy by inspecting pod status, logs, events, and resource descriptions.

## Steps
1. Start a local cluster (`minikube start` or `kind create cluster`) if you don’t already have one.
2. Deploy a broken app on purpose:
   ```bash
   kubectl create deployment broken-web --image=nginx:does-not-exist
   ```
3. Check what failed:
   ```bash
   kubectl get pods
   kubectl describe pod <pod-name>
   kubectl get events --sort-by=.lastTimestamp
   ```
4. Fix the image:
   ```bash
   kubectl set image deployment/broken-web nginx=nginx:1.27
   ```
5. Watch recovery:
   ```bash
   kubectl rollout status deployment/broken-web
   kubectl get pods -w
   ```
6. Capture the before/after findings in notes: root cause, signal that exposed it fastest, and exact fix.

## Expected Output Artifact
A short triage note with:
- failing symptom
- root cause
- 3 commands that were most useful
- fixed deployment screenshot or pasted terminal output

## Stretch Challenge
Repeat the exercise with a different failure mode: set an invalid readiness probe and diagnose why the pod runs but never becomes Ready.
