# Mission: Add an AI-Ready Health Check to a Container

#learning #mission #ai #devops #science

[[Home]]

## Objective
In 45 minutes, build and verify a small containerized service with health and readiness endpoints that distinguish a live process from an AI dependency that is ready to serve requests.

## Exact steps
1. Create a minimal Python service with `GET /healthz` returning HTTP 200 when the process is alive.
2. Add `GET /readyz` that checks a simulated model dependency, such as the presence of a loaded-model flag, and returns HTTP 200 when ready or 503 when unavailable.
3. Write a Dockerfile and add a container `HEALTHCHECK` that calls `/healthz`.
4. Build and run the image locally.
5. Verify both endpoints with `curl`, then toggle the simulated model state and confirm that `/readyz` changes between 200 and 503 while `/healthz` stays 200.
6. Record the build command, run command, curl results, and one sentence explaining why liveness and readiness should be separate.

## Expected output artifact
A small folder containing `app.py`, `Dockerfile`, and `README.md` with the verification commands and observed HTTP status codes.

## Stretch challenge
Add a `/metrics` endpoint exposing a counter for readiness failures, then demonstrate that the counter increases after three failed readiness checks.
