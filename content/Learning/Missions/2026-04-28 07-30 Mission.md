## Mission Title
Docker Healthcheck + Auto-Restart Lab (DevOps)

## Objective
Build a tiny containerized service that intentionally fails, then use Docker health checks and restart policy to observe and recover from failure in a controlled way (30–60 min).

## Exact Steps
1. Create a folder `mission-healthcheck-lab` and add `app.py` (simple HTTP server with `/health` endpoint).
2. Add logic so `/health` returns `200` for ~60 seconds, then `500` afterward (simulated failure).
3. Write a `Dockerfile` for the app and build image: `docker build -t healthcheck-lab .`.
4. Run container with:
   - `--restart unless-stopped`
   - `--health-cmd` using `curl -f http://localhost:8000/health || exit 1`
   - health interval/retries (e.g., `--health-interval=10s --health-retries=3`).
5. Monitor status with `docker ps` and `docker inspect --format='{{json .State.Health}}' <container>`.
6. Capture what happens when health starts failing (timestamps + state transitions).
7. Stop/remove container and write a short summary of what restart policy did vs what health status reported.

## Expected Output Artifact
A single note or gist containing:
- `Dockerfile`
- command used to run container
- 5–10 lines of observed health/restart timeline
- 3 bullet lessons learned

## Stretch Challenge
Convert run command into a `docker-compose.yml` with a `healthcheck` block, then add a second dependent service that waits until the first service is healthy before starting.
