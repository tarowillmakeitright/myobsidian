# Mission: Build and Prove a Docker Health Check

#learning #mission #ai #devops #science

Related: [[Home]]

## Objective

In 30–60 minutes, containerize a tiny HTTP service, add a Docker `HEALTHCHECK`, and verify both healthy and unhealthy states.

## Steps

1. **Create the service (10 min):** Make a minimal Python HTTP server with a `/health` endpoint that returns HTTP 200.
2. **Write the Dockerfile (10 min):** Base it on `python:3.12-slim`, copy the app, expose its port, and start the server.
3. **Add the health check (10 min):** Use Python's standard library in `HEALTHCHECK` so no extra package is required; set a short interval and timeout.
4. **Build and run (10 min):** Build the image, run the container, then inspect `.State.Health` until it reports `healthy`.
5. **Prove failure detection (10 min):** Temporarily point the health check at a nonexistent endpoint or stop the service, rebuild/run, and confirm the state becomes `unhealthy`.
6. **Record evidence (5 min):** Save the Dockerfile and the relevant `docker inspect` output in a short README.

## Expected Output Artifact

A folder containing `app.py`, `Dockerfile`, and `README.md`, with terminal evidence showing one `healthy` and one `unhealthy` container state.

## Stretch Challenge

Add a Docker Compose file with `depends_on: condition: service_healthy`, then demonstrate that a second service waits for the first service's health check.
