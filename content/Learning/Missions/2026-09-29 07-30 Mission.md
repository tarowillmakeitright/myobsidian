# Mission: Build a Container Health-Check Lab

#learning #mission #ai #devops #science

Link: [[Home]]

## Objective

In 45 minutes, learn how Docker health checks differ from “the process is running” by building a tiny service that becomes unhealthy on demand.

## Exact steps

1. **Create the service (10 min):** Make a minimal HTTP app with `/health` returning `200`, plus a `/fail` switch that makes `/health` return `503`.
2. **Containerize it (10 min):** Add a `Dockerfile` and install `curl` or `wget` for the probe.
3. **Add the health check (10 min):** Configure `HEALTHCHECK` with a 5-second interval, 2-second timeout, and 3 retries.
4. **Run the experiment (10 min):** Start the container, inspect its healthy state, trigger `/fail`, and watch it transition to unhealthy with `docker inspect`.
5. **Record the lesson (5 min):** Write three bullets explaining what the probe detected, how long failure detection took, and why health status alone does not restart a plain Docker container.

## Expected output artifact

A small folder containing the app, `Dockerfile`, and `README.md` with the commands used plus healthy/unhealthy inspection output.

## Stretch challenge

Add a Compose file with a dependent service gated by `condition: service_healthy`, then observe startup behavior when the first service is unhealthy.
