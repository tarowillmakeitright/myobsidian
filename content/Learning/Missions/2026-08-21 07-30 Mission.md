# Mission: Build an AI-Assisted Incident Triage Runbook

[[Home]]

#learning #mission #ai #devops #science

## Objective

In 30–60 minutes, create and test a reusable prompt that turns raw service logs into a concise incident assessment without letting the model invent evidence.

## Exact steps

1. Spend 10 minutes creating a small `sample.log` with 15–30 lines: normal requests, one burst of 5xx errors, a timeout, timestamps, and one misleading warning.
2. Write a triage prompt requiring four sections: **Observed facts**, **Likely causes**, **Missing evidence**, and **Next three checks**. Require every factual claim to cite an exact log line or timestamp.
3. Run the prompt with any local or hosted LLM using `sample.log` as input.
4. Spend 10 minutes auditing the answer: mark unsupported claims, missed signals, and checks that are too vague to execute.
5. Revise the prompt once, rerun it, and compare the two responses in a short scorecard (accuracy, evidence discipline, and actionability; each scored 1–5).

## Expected output artifact

A Markdown file named `incident-triage-runbook.md` containing the final prompt, sample log, best model response, audit notes, and before/after scorecard.

## Stretch challenge

Add a machine-readable JSON output schema with fields for `severity`, `evidence`, `hypotheses`, `confidence`, and `next_checks`, then validate one response with `jq` or a JSON validator.
