## Objective

In 45 minutes, build a repeatable Python harness that compares two prompts against five test cases and reports pass rates. The goal is to practice treating prompt changes like testable code.

## Exact steps

1. **Define the cases (10 min):** Create `cases.json` with five inputs, an expected keyword or rule for each, and one edge case designed to expose ambiguity.
2. **Write two prompt versions (5 min):** Put a baseline and an improved prompt in `prompts.py`. Make the improvement explicit: role, constraints, output format, and refusal behavior.
3. **Build the runner (15 min):** Create `evaluate.py` to run every case against both prompts. Use an available model API, or a deterministic stub if no API is configured. Record prompt version, output, latency, and pass/fail.
4. **Score the results (10 min):** Print a compact comparison showing passes out of five, average latency, and which cases changed outcome.
5. **Write the conclusion (5 min):** Add three sentences to `README.md`: what improved, what regressed, and the next test you would add.

## Expected output artifact

A folder named `prompt-eval-mini/` containing:

- `cases.json`
- `prompts.py`
- `evaluate.py`
- `results.json`
- `README.md` with the comparison and conclusion

## Stretch challenge

Add a CI-friendly exit code: return nonzero when the improved prompt scores below 80% or performs worse than the baseline.
