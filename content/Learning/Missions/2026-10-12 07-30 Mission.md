# Mission: Build a Tiny AI Retrieval Evaluator

[[Home]]

**Timebox:** 45 minutes

## Objective

Measure whether a simple keyword retriever can return the correct note for five test questions, then improve it once using evidence from the failures.

## Exact steps

1. **Create a mini knowledge base (10 min):** Make `docs/` with five short `.txt` files, each covering one distinct topic (for example: Docker health checks, Kubernetes probes, embeddings, Mars geology, and solar flares). Keep each file to 4–6 sentences.
2. **Define the test set (5 min):** Create `questions.json` containing five objects with `question` and `expected_file`; write one question per document.
3. **Implement retrieval (15 min):** Write `evaluate.py` using only Python’s standard library. Lowercase and tokenize each question/document, score each document by the count of shared unique words, and return the highest-scoring filename.
4. **Evaluate (5 min):** Run `python3 evaluate.py`. Print each question, expected file, predicted file, and pass/fail, followed by accuracy as `correct / 5`.
5. **Improve once (10 min):** Inspect failures, add a small stop-word list or simple term weighting, rerun the evaluation, and record before/after accuracy plus one sentence explaining the change.

## Expected output artifact

A folder named `tiny-retrieval-eval/` containing `docs/`, `questions.json`, `evaluate.py`, and `RESULTS.md` with the baseline score, improved score, and one observed failure mode.

## Stretch challenge

Add **top-2 recall**: count a question as successful when its expected document appears among the two highest-scoring results, and compare top-1 accuracy with top-2 recall.
