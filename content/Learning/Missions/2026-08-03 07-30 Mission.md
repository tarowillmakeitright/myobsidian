# Mission: Make a Container Prove It Is Healthy

#learning #mission #ai #devops #science

[[Home]]

## Objective

In 30–60 minutes, learn how Docker health checks differ from “the process is running” by building a tiny service, adding a health check, and observing healthy and unhealthy states.

## Exact steps

1. Create a folder named `container-health-lab` with a minimal HTTP service that returns `200 OK` on `/health`.
2. Add a `Dockerfile`, then build and run the image locally.
3. Add a Docker `HEALTHCHECK` that requests `/health` every 5 seconds, with a 2-second timeout and 3 retries.
4. Use `docker inspect --format='{{json .State.Health}}' <container>` to confirm the container becomes `healthy`.
5. Break the `/health` endpoint or change the health-check path, rebuild, and observe the transition to `unhealthy`.
6. Restore the correct endpoint and write three short notes: what Docker checked, how long failure detection took, and why a running process can still be unhealthy.

## Expected output artifact

A `container-health-lab/` directory containing the service, `Dockerfile`, and `README.md` with the healthy/unhealthy observations and the two relevant `docker inspect` outputs.

## Stretch challenge

Add a `compose.yaml` with `depends_on: condition: service_healthy`, then prove that a second container waits for the first service to become healthy.
