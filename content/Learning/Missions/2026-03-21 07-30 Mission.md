## Mission Title
Build a Tiny RAG Pipeline with Local Documents

## Objective
In 30–60 minutes, build and test a minimal Retrieval-Augmented Generation (RAG) workflow that answers questions from your own notes/files.

## Exact Steps
1. Create a folder `rag-mini/` and add 3–5 short text/markdown files (your own notes or sample docs).
2. Use a simple embedding + vector store setup (e.g., Python with `sentence-transformers` + `faiss`/`chroma`) to index the files.
3. Write a script that:
   - takes a user question,
   - retrieves top 3 relevant chunks,
   - sends context + question to an LLM,
   - prints answer + cited source filenames.
4. Test with at least 3 questions:
   - one easy factual query,
   - one cross-document query,
   - one query that should fail gracefully (out-of-scope).
5. Add one safeguard: if retrieval score is too low, return “I don’t know based on provided docs.”

## Expected Output Artifact
A small runnable repo/folder containing:
- `index.py` (or notebook) for ingestion/indexing,
- `ask.py` for Q&A,
- `README.md` with setup/run commands,
- one screenshot or terminal log showing 3 test queries and outputs.

## Stretch Challenge
Add a simple evaluation file (`eval.md`) with 5 Q/A test cases and manually score answer quality (correct / partial / wrong) to estimate baseline RAG reliability.
