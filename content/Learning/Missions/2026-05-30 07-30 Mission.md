# Mission: Build a Lightweight RAG Evaluator (30–60 min)

## Objective
Create a tiny, repeatable script that tests retrieval quality for a local RAG setup by measuring whether the top-3 results contain the expected source chunk.

## Exact Steps
1. **Prepare a mini dataset (10 min):**
   - Make a `data/` folder with 5 short markdown docs (different topics).
   - Create `queries.json` with 8 queries and expected doc IDs.
2. **Implement retrieval loop (15–20 min):**
   - Use your existing embedding+vector store tool (or simple cosine over sentence embeddings).
   - For each query, retrieve top-3 docs.
   - Log: query, expected doc, retrieved docs.
3. **Score results (10 min):**
   - Compute `Recall@3 = matched_queries / total_queries`.
   - Print failures (queries where expected doc not in top-3).
4. **Make it repeatable (10 min):**
   - Add a one-command run script (`run_eval.sh` or `make eval`).
   - Save outputs to `results/YYYY-MM-DD-rag-eval.md`.

## Expected Output Artifact
- `results/2026-05-30-rag-eval.md` containing:
  - Recall@3 score
  - Failure cases
  - One paragraph: “What to improve next”

## Stretch Challenge
Add a second retrieval config (e.g., different chunk size or embedding model) and compare both configs side-by-side in the same report.
