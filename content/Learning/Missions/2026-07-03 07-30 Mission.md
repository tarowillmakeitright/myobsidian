## Mission Title
Trace an AWS IAM access path like a security engineer

## Objective
Learn how IAM policies actually grant or deny access by analyzing one realistic AWS permission scenario end to end in 30–60 minutes.

## Exact Steps
1. Pick one AWS action to study: `s3:GetObject`, `ssm:GetParameter`, or `ec2:StartInstances`.
2. Read the AWS docs page for that action and note:
   - required resource type
   - common condition keys
   - whether wildcard `*` is often used badly
3. Create three tiny example policies in your notes:
   - one that allows too much
   - one least-privilege version
   - one explicit deny example
4. For each policy, write 2–3 sentences explaining why the request would be allowed or denied.
5. Draw a simple decision flow:
   - identity policy
   - resource policy
   - permissions boundary / SCP if relevant
   - explicit deny wins
6. Finish with one “rule of thumb” you’d use in a real cloud review.

## Expected Output Artifact
A one-page note containing:
- the chosen AWS action
- the 3 sample policies
- your allow/deny explanations
- a small IAM decision flow
- one practical security rule of thumb

## Stretch Challenge
Use the AWS Policy Simulator or an online IAM policy evaluator to test your least-privilege policy and refine it until it is as narrow as possible without breaking the action.
