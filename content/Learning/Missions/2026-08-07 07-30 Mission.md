# Mission: Build a Container Health-Check Harness

[[Home]]

#learning #mission #ai #devops #science

## Objective

In 30–60 minutes, learn how Docker health checks distinguish a running container from a healthy service by building and testing a tiny HTTP service with a deliberate failure mode.

## Exact steps

1. Create a folder named `container-health-mission` with a minimal Python HTTP server that exposes `/health` and returns HTTP 200.
2. Add a `Dockerfile` that starts the server and defines a `HEALTHCHECK` using Python or `curl` against `/health`.
3. Build the image: `docker build -t health-mission .`
4. Run it: `docker run --name health-mission -d -p 8080:8080 health-mission`
5. Inspect health transitions with `docker inspect --format='{{json .State.Health}}' health-mission` and `docker ps`.
6. Break the health endpoint or change its expected path, rebuild/restart, and observe the container become `unhealthy` while its process remains running.
7. Restore the endpoint, rerun, and record the recovery behavior and timing.
8. Clean up the test container with `docker rm -f health-mission`.

## Expected output artifact

A small `container-health-mission/` project containing the server, `Dockerfile`, and a `README.md` with the healthy/unhealthy observations and one captured `docker inspect` result.

## Stretch challenge

Add a Docker Compose file with a second service that waits for `health-mission` using `depends_on: condition: service_healthy`, then prove it does not start while the first service is unhealthy.
