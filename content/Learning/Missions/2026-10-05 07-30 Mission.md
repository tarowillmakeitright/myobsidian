# Mission: Add an AI-assisted incident runbook check

[[Home]]

## Objective

In 30–60 minutes, build a small script that turns a short service log into a structured incident summary with probable cause, evidence, and next actions—while keeping the output reproducible and reviewable.

## Exact steps

1. Create a sample `incident.log` with 15–30 lines containing one clear failure pattern (for example: rising latency followed by database connection-pool exhaustion).
2. Write a prompt template that requires four sections: **Symptoms**, **Evidence**, **Probable cause**, and **Next checks**. Require every claim to cite a log line number.
3. Write a minimal script in Python or shell that numbers the log lines, inserts them into the prompt, and saves the model response to `incident-summary.md`. If no model API is configured, paste the generated prompt into your preferred local/chat model manually.
4. Review the response against the source log. Mark unsupported claims and revise the prompt once to reduce hallucinations.
5. Add a final **Human verdict** section stating whether the probable cause is supported, uncertain, or rejected.

## Expected output artifact

`incident-summary.md` containing a line-cited incident analysis, the revised prompt, and a human verdict.

## Stretch challenge

Add a tiny validation step that flags any cited line number that does not exist in `incident.log`.
