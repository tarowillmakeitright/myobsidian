## Mission Title
Build a Tiny RAG Evaluator (AI + DevOps mindset)

## Objective
In 30–60 minutes, create a minimal script that compares two retrieval settings for the same small document set and reports which one returns more relevant context for a fixed query set.

## Exact Steps
1. Create a folder `rag-mini-eval/` with 5–10 short text docs (can be your notes or sample snippets).
2. Define 5 evaluation queries with a clear “expected doc” for each in a small JSON file.
3. Implement retrieval setting A (e.g., simple keyword/BM25 or naive substring scoring).
4. Implement retrieval setting B (e.g., chunked retrieval with different chunk size or top-k).
5. For each query, retrieve top-3 docs from A and B, then mark hit@3 = 1 if expected doc appears, else 0.
6. Print a concise comparison table: query, hit@3(A), hit@3(B), winner.
7. Write a 5-line conclusion: which setup performed better and why.

## Expected Output Artifact
- A small repo/folder containing:
  - `docs/` (source texts)
  - `queries.json`
  - `eval.py` (or `eval.js`)
  - `results.md` with comparison table + conclusion

## Stretch Challenge
Add a latency column (ms/query) for both settings and choose the best **quality/speed tradeoff** instead of only best hit rate.
