# Mission: Build an AI-Assisted Incident Runbook

#learning #mission #ai #devops #science

Links: [[Home]]

## Objective

Create and test a concise runbook that helps diagnose a failing containerized web service using logs, health checks, and a small AI-ready evidence bundle. Timebox: 45 minutes.

## Steps

1. **Pick a service (5 min):** Use a small Dockerized app you already have, or run `nginx:alpine`. Record its expected healthy behavior.
2. **Inject one failure (5 min):** Choose a reversible fault—wrong port mapping, invalid config, or stopped container.
3. **Collect evidence (10 min):** Capture `docker ps -a`, `docker logs <container>`, `docker inspect <container>`, and one `curl -v` health-check result.
4. **Build the runbook (15 min):** Write a decision tree covering symptom, evidence command, likely cause, corrective action, and verification command. Add a short prompt that gives an AI assistant only the evidence needed to suggest the next diagnostic step.
5. **Test and refine (10 min):** Follow the runbook from a clean terminal, repair the fault, verify the health check passes, and note one ambiguous or missing instruction.

## Expected Output Artifact

A Markdown runbook named `container-incident-runbook.md` containing the decision tree, evidence bundle template, AI diagnostic prompt, repair steps, and successful verification output.

## Stretch Challenge

Turn the health check and evidence collection into a single read-only shell script that exits nonzero when the service is unhealthy.
