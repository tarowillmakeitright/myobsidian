# Mission: CI Secret Leak Check in GitHub Actions

**Objective**
Learn how secrets can accidentally leak in CI logs, then harden a simple GitHub Actions workflow against that risk.

**Steps**
1. Create a small test repo or use a scratch repo with a basic GitHub Actions workflow.
2. Add one fake secret locally in repo settings, such as `DEMO_API_KEY=test-12345`.
3. Write a workflow that prints environment variables in an unsafe way and identify why that is risky.
4. Replace the unsafe step with a safer pattern: pass only the needed secret to one step and avoid broad env dumps.
5. Add one extra hardening improvement: pin an action version, reduce permissions, or separate build/test from deploy.
6. Write a short note: “what leaked risk existed, what I changed, and why it is safer.”

**Expected output artifact**
A markdown note or commit showing:
- the before/after workflow snippet
- one sentence on the leak risk
- one sentence on the mitigation
- one extra hardening improvement

**Stretch challenge**
Add explicit `permissions:` to the workflow with least privilege and explain each permission in 2-3 bullets.
