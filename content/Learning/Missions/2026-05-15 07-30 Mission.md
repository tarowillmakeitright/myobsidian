## Objective
Implement and benchmark prompt caching for one LLM API workflow so repeated requests are faster and cheaper, then document the measured impact.

## Exact Steps
1. Pick one existing prompt workflow you run often (chat summarizer, code explainer, etc.).
2. Add a cache key strategy:
   - Stable key from: model + system prompt hash + user prompt hash (normalized).
   - TTL: 24h.
3. Implement cache layer (Redis or local SQLite/file cache if quicker).
4. Run benchmark:
   - 10 uncached requests (cold run), log avg latency + token/cost.
   - 10 cached-eligible requests (warm run), log avg latency + token/cost.
5. Compare results and write a short conclusion (what improved, by how much, any caveats).

## Expected Output Artifact
A short note in this file section or a sibling note containing:
- Cache key format
- Before/after metrics table (latency + cost)
- 3–5 bullet lessons learned

## Stretch Challenge
Add cache invalidation by prompt-version header (e.g., `prompt_version=v2`) so you can roll prompts safely without stale responses.
