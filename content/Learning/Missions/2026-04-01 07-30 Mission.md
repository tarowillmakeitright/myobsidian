## Mission Title
Docker Healthcheck Lab: Build a Self-Healing FastAPI Service

## Objective
Learn core DevOps reliability patterns by containerizing a tiny API, adding a healthcheck, and validating auto-restart behavior with Docker Compose (30–60 min).

## Exact Steps
1. Create a folder `mission-fastapi-healthcheck`.
2. Add `app.py` with two routes:
   - `GET /` returns `{ "status": "ok" }`
   - `GET /health` returns HTTP 200 and `{ "health": "up" }`
3. Add `requirements.txt` with:
   - `fastapi`
   - `uvicorn`
4. Add a `Dockerfile`:
   - Use `python:3.12-slim`
   - Install dependencies
   - Expose port `8000`
   - Start with `uvicorn app:app --host 0.0.0.0 --port 8000`
5. Add `docker-compose.yml` with one service:
   - Build from current directory
   - Map `8000:8000`
   - `restart: always`
   - Add healthcheck hitting `/health` every 10s (with timeout/retries)
6. Run `docker compose up --build -d`.
7. Verify:
   - `curl http://localhost:8000/`
   - `docker ps` shows container as `healthy`
8. Simulate failure:
   - Temporarily change `/health` to return HTTP 500
   - Rebuild/restart
   - Observe container marked `unhealthy`
9. Restore healthy endpoint and confirm status returns to `healthy`.

## Expected Output Artifact
A Git repo or folder containing:
- `app.py`
- `requirements.txt`
- `Dockerfile`
- `docker-compose.yml`
- A short `README.md` with 3 screenshots/command outputs:
  1) service running, 2) unhealthy state, 3) recovered healthy state.
