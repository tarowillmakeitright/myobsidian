# Edge Logs to Insight: Build a Tiny DevOps Failure Triage Flow

#learning #mission #ai #devops #science
[[Home]]

## Objective
Use shell tools plus a small AI prompt to turn a noisy log sample into a short incident summary with the likely root cause and next action.

## Exact Steps
1. Create a working folder: `mkdir -p ~/tmp/mission-logs && cd ~/tmp/mission-logs`
2. Save a sample log file with 20-50 mixed lines (INFO/WARN/ERROR). Either copy from a real non-sensitive service log or generate one.
3. Use command-line filtering to isolate the signal:
   - `grep -E 'ERROR|WARN|timeout|failed|exception' sample.log`
   - `sort | uniq -c`
   - optional: `tail -n 30 sample.log`
4. Identify the top 1-2 repeating failure patterns.
5. Feed only the filtered, non-sensitive lines into your preferred AI tool with this prompt:
   - “Summarize the incident in 5 bullets: symptom, likely cause, confidence, immediate fix, and one follow-up prevention step.”
6. Write a final incident note in markdown.

## Expected Output Artifact
A markdown note named `incident-summary.md` containing:
- 5-bullet summary
- top repeated error pattern
- one immediate action
- one prevention action

## Stretch Challenge
Turn the flow into a reusable script (`triage.sh`) that filters a log file and outputs a clean snippet ready to paste into an AI prompt.
