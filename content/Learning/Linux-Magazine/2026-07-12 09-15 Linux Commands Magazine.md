# Daily Linux Commands Magazine

## 1) 今日の1コマンド
`watch` — コマンドを一定間隔で再実行し、状態変化をその場で追える監視向けコマンド。

## 2) 実務で使う場面
- デプロイ直後に `systemctl status` や `kubectl get pods` を数秒ごとに見て、復旧や起動完了を確認するとき
- 障害対応で `ss -tulpn` や `df -h` を繰り返し見て、ポートやディスク状況の変化を追うとき
- CI/CD やバッチ処理中に `ps`, `nvidia-smi`, `ls -lh` などの出力を定期確認したいとき
- ログ以外の「現在状態」を軽く監視したいが、わざわざ監視ツールを立てるほどではないとき

## 3) よく使うオプション
- `-n 2` — 2秒ごとに実行。デフォルトは 2 秒だが、明示すると意図が伝わりやすい
- `-d` — 前回との差分をハイライト。値の変化を見つけやすい
- `-t` — ヘッダー（時刻・間隔・コマンド行）を消す。画面をすっきりさせたいときに便利
- `-g` — 出力が変わるまで終了しない。変化待ちの簡易トリガーとして使える
- `-b` — ビープ音で変化を通知。手元で別作業しているとき向き

## 4) 実例コマンド
```bash
watch -n 2 'systemctl status nginx --no-pager'
```
nginx の状態変化を 2 秒ごとに確認する。

```bash
watch -d 'kubectl get pods -A'
```
Pod の再起動や Running 化などの変化を強調表示する。

```bash
watch -n 1 'ss -tulpn | grep 8080'
```
8080 番ポートをプロセスが掴んだかを 1 秒ごとに確認する。

```bash
watch -n 5 'df -h / /var'
```
ルートと `/var` のディスク使用量を 5 秒ごとに見る。

```bash
watch -g 'ls -lh /var/log/app.log'
```
ログファイルサイズが変わるまで待ち、変わったら抜ける。

```bash
watch -t -n 2 'ps -eo pid,comm,%cpu,%mem --sort=-%cpu | head'
```
CPU を多く使うプロセス上位を、ヘッダーなしで追う。

## 5) よくあるミスと安全ポイント
- **引用符を忘れる**: パイプや `grep` を含むときは `'...'` で囲む。囲わないと親シェル側で先に解釈される
- **間隔を短くしすぎる**: `-n 0.1` のような高頻度実行は対象コマンドやサーバーに無駄な負荷をかけやすい
- **副作用のあるコマンドを流さない**: `rm`, `mv`, `systemctl restart` などを `watch` で回すのは危険。基本は読み取り系だけにする
- **色付き出力が崩れることがある**: コマンドによっては `--color=always` や `--no-pager` を併用した方が見やすい

## 6) 追加学習
- `man watch` では **`-d` / `-g` / `-n`** の違いをまず読むと実務で使いやすい
- 関連コマンド: `while true; do ...; sleep 2; done`（より柔軟な自作ループ）、`tail -f`（ログ追跡専用）
