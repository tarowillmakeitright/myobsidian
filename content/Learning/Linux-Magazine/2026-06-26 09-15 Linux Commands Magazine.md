1) 今日の1コマンド
`lsof` — プロセスが「どのファイル・ソケット・ポートを開いているか」を特定する調査コマンド。

2) 実務で使う場面
- `:3000` や `:8080` が使用中で、どのプロセスが握っているか調べる
- ログローテーション後も容量が減らないとき、削除済みファイルを掴み続けるプロセスを見つける
- アプリがどの設定ファイル・UNIXソケット・証明書を開いているか確認する
- デプロイ後の疎通確認で、特定サービスの待受や接続先を追う

3) よく使うオプション
- `-i` : ネットワーク関連のファイルだけ表示する（TCP/UDP）
- `-P` : ポート番号をサービス名に変換せず、そのまま数字で表示する
- `-n` : IPアドレスやホスト名の名前解決をしない。表示が速く、調査向き
- `-p <PID>` : 特定PIDが開いているものだけ見る
- `+L1` : 削除済みだがまだ開かれているファイルを探す

4) 実例コマンド
```bash
lsof -iTCP:3000 -sTCP:LISTEN -Pn

sudo lsof -i :443 -Pn

lsof -p 12345

sudo lsof +L1

lsof /var/log/nginx/access.log

sudo lsof -u nginx -a -iTCP -Pn
```

5) よくあるミスと安全ポイント
- 名前解決ありのままだと遅く見えることがある。まずは `-Pn` を付けると安定
- 他ユーザーのプロセスや一部システム情報は見えないことがある。必要なら `sudo` を使う
- `lsof -i` だけだと情報量が多い。ポート番号、PID、ユーザーで絞ると実務向き
- 削除済みファイルを見つけても、いきなり kill せず対象サービスを確認してから再起動する

6) 追加学習
- `man lsof` の「`-i`」「`-p`」「`+L1`」「検索条件の AND に使う `-a`」あたりは実務でよく使う
- 関連コマンド: `ss`（接続確認）, `fuser`（そのファイル/ポートを使うPID確認）, `ps`（プロセス詳細確認）
