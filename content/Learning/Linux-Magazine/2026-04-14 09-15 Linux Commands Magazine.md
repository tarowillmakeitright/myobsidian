## 1) 今日の1コマンド
**`ss`** — LinuxでTCP/UDPソケットの状態を高速に確認できる、`netstat`の実用的な後継コマンド。

## 2) 実務で使う場面
- アプリが「ポートを開いているか」をデプロイ後に即確認したいとき
- 障害時に「どこへ接続中か（ESTAB）」を把握したいとき
- 特定ポート（例: 80/443/5432）を誰がListenしているか確認したいとき
- 接続数増加（輻輳・リーク）を一次切り分けしたいとき

## 3) よく使うオプション
- `-l` : Listen中ソケットのみ表示（待受確認に最重要）
- `-t` : TCPのみ表示
- `-u` : UDPのみ表示
- `-n` : 名前解決せず数値表示（高速・誤解減）
- `-p` : プロセス情報表示（要権限、原因プロセス特定に有効）
- `-a` : すべての状態を表示（LISTEN/ESTAB等）

## 4) 実例コマンド
```bash
# 1) まず全体のTCP待受を確認（名前解決なし）
ss -ltn

# 2) 443番ポートを誰がListenしているか確認
sudo ss -ltnp '( sport = :443 )'

# 3) PostgreSQL(5432)の待受確認
ss -ltn '( sport = :5432 )'

# 4) 現在の確立済みTCP接続を確認
ss -tn state established

# 5) nginx関連プロセスの接続だけ確認
sudo ss -tnp | grep nginx

# 6) UDP待受の確認（DNS/NTPトラブル時など）
ss -lun
```

## 5) よくあるミスと安全ポイント
- **ミス:** `-n` なしで実行してDNS逆引きで遅くなる
  - **安全:** 調査初動は `-n` を基本にする
- **ミス:** `-p` が見えず「プロセス不明」と誤判断
  - **安全:** 必要時だけ `sudo` で `ss -p` を使う
- **ミス:** LISTEN確認だけで疎通OKだと思い込む
  - **安全:** `ss` はローカル状態確認。外部疎通は `curl`/`nc` 等で別途確認

## 6) 追加学習
- まず `man ss` の **FILTER** セクション（`sport` / `dport` / `state`）を読むと実務効率が一気に上がる
- 関連コマンド: `ip`（経路/IF確認）, `lsof -i`（FD視点の確認）
