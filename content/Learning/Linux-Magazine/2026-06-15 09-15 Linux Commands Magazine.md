## 1) 今日の1コマンド（command name + one-line summary）
**`df`** — ファイルシステムごとのディスク使用量と空き容量を素早く確認するコマンド。

## 2) 実務で使う場面
- 本番サーバーで「容量不足が原因で書き込み失敗していないか」を確認するとき
- ログ肥大化やバックアップ失敗の前に、空き容量を定期点検するとき
- Docker ホストや CI サーバーで、どのマウント先が逼迫しているか切り分けるとき
- 監視アラート後に、対象ボリュームの使用率を即確認するとき

## 3) よく使うオプション
- `-h` — 人間に読みやすい単位（GiB, MiB など）で表示
- `-T` — ファイルシステム種別も表示（ext4, xfs, tmpfs など）
- `-x <type>` — 指定したファイルシステム種別を除外
- `--output=...` — 欲しい列だけを指定して見やすく出す
- `-i` — 容量ではなく inode 使用状況を確認

## 4) 実例コマンド
```bash
df -h
```
容量をざっと確認する定番。

```bash
df -hT
```
容量とファイルシステム種別をまとめて確認。

```bash
df -h /var
```
`/var` が載っている実際のファイルシステムだけ確認。

```bash
df -h -x tmpfs -x devtmpfs
```
一時領域を除外して、実ディスクだけ見たいとき。

```bash
df --output=source,fstype,size,used,avail,pcent,target -h
```
監視・報告用に必要な列だけ整えて表示。

```bash
df -i /var/log
```
inode 枯渇の確認。小さいファイルが大量にある環境で有効。
```

## 5) よくあるミスと安全ポイント
- `df` は**ファイル単位の犯人探しには向かない**。どのディレクトリが重いかは `du` を使う
- 「容量は空いているのに書けない」場合、**inode 枯渇**の可能性があるので `df -i` も見る
- `tmpfs` や `overlay` を見て混乱しやすい。必要なら `-x` で除外する
- コンテナ内の `df` は、ホスト側の実容量感とズレることがある。必要ならホストでも確認する

## 6) 追加学習
- `man df` の **`--output`** と **`-i`** の節は実務でかなり使える
- 関連コマンド: `du`, `lsblk`, `mount`
