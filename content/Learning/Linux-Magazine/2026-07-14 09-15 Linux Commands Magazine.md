# Daily Linux Commands Magazine

## 1) 今日の1コマンド
`ss` — ソケット・TCP/UDP・待受ポートを高速に確認できる、現場向けのネットワーク確認コマンド。

## 2) 実務で使う場面
- アプリが想定ポートで待ち受けしているかをデプロイ直後に確認するとき
- 「接続できない」「ポートが開かない」と言われたときに、LISTEN 状態や接続数を調べるとき
- どのプロセスが 80/443/5432 などのポートを掴んでいるかを特定したいとき
- 一時的な大量接続や TIME-WAIT 増加を見て、通信まわりの異常兆候を確認するとき

## 3) よく使うオプション
- `-t` — TCP ソケットだけ表示。Web/API 調査で最もよく使う
- `-u` — UDP ソケットだけ表示。DNS や syslog 系の確認向き
- `-l` — LISTEN 中だけ表示。待受ポート確認で定番
- `-p` — プロセス情報も表示。どのサービスが掴んでいるか分かる
- `-n` — 名前解決をしない。表示が速く、スクリプトでも安定
- `-a` — LISTEN 以外も含めて全部表示。接続状況全体を見たいときに使う

## 4) 実例コマンド
```bash
ss -tuln
```
TCP/UDP の待受ポートを名前解決なしで一覧表示する。

```bash
ss -ltnp
```
現在 LISTEN している TCP ポートと、そのプロセスを確認する。

```bash
ss -tn state established
```
確立済みの TCP 接続だけを確認する。

```bash
ss -ltnp '( sport = :443 )'
```
443 番ポートをどのプロセスが待ち受けているか調べる。

```bash
ss -tan | grep ':5432 '
```
PostgreSQL 向けの 5432 接続状況をざっくり確認する。

```bash
ss -s
```
ソケット全体のサマリーを見て、接続数の偏りや増加を把握する。

## 5) よくあるミスと安全ポイント
- **`netstat` 感覚で遅さを期待しない**: `ss` は速いが、表示対象が多いと出力も多い。まずは `-l` やポート絞り込みを使うと見やすい
- **`-p` は権限不足に注意**: 他ユーザーのプロセス情報は `sudo` が必要なことがある
- **ホスト名解決で混乱しない**: 調査時は `-n` を付けて IP/ポートをそのまま見る方が確実
- **待受と接続中を混同しない**: `-l` は待受確認、`state established` は接続中確認。目的に応じて使い分ける

## 6) 追加学習
- `man ss` では **`STATE-FILTER`** と **`EXPRESSION`** の書式を読むと一気に実務で使いやすくなる
- 関連コマンド: `ip`（経路・IP確認）, `lsof -i`（ポートとファイル/プロセス対応確認）, `tcpdump`（実パケット確認）
