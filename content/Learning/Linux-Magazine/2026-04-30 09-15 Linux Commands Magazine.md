# 2026-04-30 Linux Commands Magazine
[[Home]]

## 1) 今日の1コマンド（command name + one-line summary）
**`lsof`** — 「どのプロセスが、どのファイル/ポートを掴んでいるか」を特定するトラブルシュート定番コマンド。

## 2) 実務で使う場面（2-4 concrete scenarios）
- デプロイ時に「ポート 8080 が使用中」で起動失敗した原因プロセスを特定する。
- ログローテート後もディスク使用量が減らないとき、削除済みファイルを握っているプロセスを見つける。
- NFS マウント解除できないとき、対象ディレクトリを使用中のプロセスを洗い出す。
- セキュリティ調査で、不審な外向き通信をしているPIDを確認する。

## 3) よく使うオプション（at least 3 options with explanation）
- **`-i`**: ネットワーク関連（TCP/UDP）を表示（例: `-iTCP:443`）。
- **`-p <PID>`**: 特定プロセスが開いているFDだけ表示。
- **`+D <dir>`**: 指定ディレクトリ配下を掴んでいるプロセスを再帰的に検索。
- **`-n -P`**: 名前解決を無効化して高速化（IP/ポート番号をそのまま表示）。

## 4) 実例コマンド（at least 5 examples, copy-paste ready）
```bash
# 1) 8080を使っているプロセスを確認
lsof -iTCP:8080 -sTCP:LISTEN -n -P

# 2) PID 1234 が開いているファイル/ソケットを確認
lsof -p 1234

# 3) /var/log 配下を掴んでいるプロセスを確認（アンマウント不可時にも有効）
lsof +D /var/log

# 4) 削除済みなのに開かれ続けているファイルを確認（容量逼迫調査）
lsof -nP | grep '(deleted)'

# 5) 現在のユーザーが開いているネットワーク接続を確認
lsof -a -u "$USER" -i -n -P
```

## 5) よくあるミスと安全ポイント
- `lsof +D` は重い（I/O多い）ので、大きなディレクトリでの常用は注意。
- 情報不足で見えない場合は `sudo` を付ける（権限不足の可能性が高い）。
- `grep` だけで即 kill せず、**COMMAND/PID/接続先**を必ず二重確認してから対処する。

## 6) 追加学習（manページの読みどころ or related command）
- まずは `man lsof` の **"NETWORK FILES"** と **"OUTPUT"** を読むと、現場で必要な読み方が一気に掴める。
- 関連コマンド: `ss`（接続状態の俯瞰）、`fuser`（ファイル/ポート使用PIDの簡易特定）。
