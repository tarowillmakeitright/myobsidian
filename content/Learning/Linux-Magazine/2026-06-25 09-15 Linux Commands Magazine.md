1) 今日の1コマンド
`du` — ディレクトリやファイルが実際にどれだけ容量を使っているかを調べるコマンド。

2) 実務で使う場面
- サーバーのディスク逼迫時に、どのディレクトリが肥大化しているか切り分ける
- `/var/log` や `/tmp` の増加原因を調査する
- ビルド成果物や Docker 関連キャッシュの容量を確認する
- デプロイ前にアプリ配下のサイズ感をざっくり把握する

3) よく使うオプション
- `-h` : 人間に読みやすい単位で表示する（KB/MB/GB）
- `-s` : 合計サイズだけを表示する
- `-d N` : 表示する深さを制限する（例: `-d 1`）
- `-x` : 別ファイルシステムをまたがない
- `--apparent-size` : 実ディスク消費ではなく見かけ上のサイズで見る

4) 実例コマンド
```bash
du -sh /var/log

du -h -d 1 /var

du -h -d 1 /home/$USER | sort -h

du -sh ./*

du -xhd 1 /

du -sh --apparent-size ./backup.tar
```

5) よくあるミスと安全ポイント
- `du -h /` を深さ制限なしで打つと、出力が多すぎて見づらい。まずは `-d 1` か `-s` を使う
- 別マウント先まで含めると結果がブレやすい。サーバー調査では `-x` が便利
- 権限不足で `Permission denied` が出ることがある。必要なら `sudo` で再実行する
- `du` は実ディスク使用量を見る。ファイルサイズ確認だけなら `ls -lh` や `stat` のほうが適切なこともある

6) 追加学習
- `man du` の「`--max-depth`」「`--apparent-size`」「`-x`」は実務で特に重要
- 関連コマンド: `df`（ファイルシステム全体の空き容量確認）、`sort -h`（容量順ソート）
