## 1) 今日の1コマンド（command name + one-line summary）
**`du`** — ディスク使用量をディレクトリ単位で素早く把握し、容量逼迫や肥大化調査に直結する定番コマンド。

## 2) 実務で使う場面（2-4 concrete scenarios）
- **容量不足の一次調査**: `/var`, `/home`, `/srv` のどこが膨らんでいるか切り分ける。
- **ログ肥大の確認**: アプリログや `journal` 保存領域の増え方をざっくり把握する。
- **CI/CD・ビルド環境の掃除判断**: キャッシュ、成果物、コンテナ関連ディレクトリの重さを確認する。
- **バックアップ前の見積もり**: 転送・退避前に対象サイズ感を掴む。

## 3) よく使うオプション（at least 3 options with explanation）
- `-h` : 人間向け表示。`K`, `M`, `G` で見やすい。
- `-s` : 合計のみ表示。対象ごとの総量を手早く見たい時に便利。
- `-d N` : 深さを制限して表示。`-d 1` なら1階層だけ確認できる。
- `-x` : 別ファイルシステムをまたがない。マウントポイント混在時の誤読防止に有効。
- `-a` : ファイル単位も含めて表示。犯人ファイルを掘る時に使う。

## 4) 実例コマンド（at least 5 examples, copy-paste ready）
```bash
# 1) /var 配下の1階層目だけをざっくり確認
sudo du -h -d 1 /var

# 2) 主要ディレクトリの合計サイズを比較
sudo du -sh /var /home /srv

# 3) / 配下で別FSをまたがずに大きい場所を探す
sudo du -x -h -d 1 /

# 4) アプリログ配下で重いディレクトリを確認
sudo du -h -d 2 /var/log/myapp

# 5) カレント配下のサイズを大きい順に並べる
sudo du -h -d 1 . | sort -h

# 6) ファイル単位まで掘って上位20件を見る
sudo du -ah /srv/app | sort -h | tail -n 20
```

## 5) よくあるミスと安全ポイント
- `du` は**見えているパスの使用量**を集計する。`df` の空き容量とは視点が違うので混同しない。
- マウントポイントをまたぐと数字が膨らみやすい。ルート配下調査では **`-x` を付ける**と安全。
- 権限不足で一部見えないと、実態より小さく見える。システム領域は `sudo` 前提で確認する。
- 削除済みだがプロセスが掴んでいるファイルは `du` に出ないことがある。空き容量差分が不自然なら `lsof` も確認。

## 6) 追加学習（manページの読みどころ or related command）
- `man du` は **`--max-depth`**, **`--separate-dirs`**, **`--exclude`** 周辺を読むと現場で使いやすい。
- 関連: `df`（ファイルシステム全体の空き容量）, `sort -h`（人間向けサイズの並び替え）, `lsof`（削除済みオープンファイル確認）。
