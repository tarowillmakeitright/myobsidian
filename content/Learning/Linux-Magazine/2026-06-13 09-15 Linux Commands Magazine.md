## 1) 今日の1コマンド（command name + one-line summary）
**`lsof`** — 「そのファイル/ポートを誰が使っているか」を即確認できる、障害調査の定番コマンド。

## 2) 実務で使う場面（2-4 concrete scenarios）
- **ポート競合の調査**: `:3000` や `:8080` が既に使われていてアプリが起動しないとき。
- **アンマウントできない原因調査**: ディレクトリやマウントポイントを掴んでいるプロセスを探したいとき。
- **ログローテート/削除前の確認**: 削除したいログをまだ掴んでいるプロセスがないか確認するとき。
- **ユーザー別の資源確認**: 特定ユーザーの開いているファイルや接続をざっと見たいとき。

## 3) よく使うオプション（at least 3 options with explanation）
- **`-i`**: ネットワーク関連だけを見る。`-i :8080` や `-i TCP:22` のように絞れる。
- **`-n`**: ホスト名解決をしない。表示が速くなり、DNS待ちを避けられる。
- **`-P`**: ポート番号をサービス名変換しない。`http` ではなく `80` で見える。
- **`-p <PID>`**: 特定プロセスが開いているファイル/ソケットだけ見る。
- **`-u <user>`**: 特定ユーザーの開いているものだけを見る。
- **`+D <dir>`**: 指定ディレクトリ配下を開いているプロセスを探す。

## 4) 実例コマンド（at least 5 examples, copy-paste ready）
```bash
lsof -nP -i :3000
lsof -nP -i TCP:8080
sudo lsof +D /var/log/myapp
lsof -p 12345
lsof -u nginx
sudo lsof /var/lib/docker/containers/abcd1234/abcd1234-json.log
```

## 5) よくあるミスと安全ポイント
- **`sudo` が必要なことが多い**: 他ユーザーやシステムプロセスは一般権限だと見えないことがある。
- **`+D` は重い**: 大きいディレクトリで使うと遅い。まずは対象ファイルを直接指定できないか考える。
- **`-nP` を付けないと遅く見える**: 名前解決で待たされて「固まった？」となりがち。
- **LISTEN と ESTABLISHED を見分ける**: 待受中なのか、実通信中なのかで原因が違う。
- **確認だけで終わらせない**: 見つけたPIDを止める前に、本当にそのプロセスを落としてよいか確認する。

## 6) 追加学習（manページの読みどころ or related command）
- **`man lsof` の読みどころ**: `-i`, `-p`, `-u`, `+D`, `-a` の組み合わせ。
- **関連コマンド**: `ss`（通信状態確認）, `fuser`（ファイル/ポート使用中プロセス確認）, `ps`（プロセス詳細確認）。
